# ياسمين ستور | Accessorati

متجر عربي بتصميم زهري: React 19، وASP.NET Core 10، وPostgreSQL وAuth وStorage على Supabase. الطلبات بالدفع عند الاستلام.

## حالة المشروع

الكود قابل للبناء، لكنه يحتاج إعداد Supabase وحساب الإدارة والاستضافة، ثم اختبار التكامل الفعلي قبل البيع. وضع المعاينة يعرض منتجات توضيحية ويمنع إنشاء طلبات. لا يوجد أدمن افتراضي.

## التشغيل محليًا

المتطلبات: Node.js 24 و.NET SDK 10.

```sh
cd client
npm ci
npm run build
cd ../server
dotnet run --no-launch-profile --urls http://localhost:5080 --environment Development
```

المتجر على `/`، ولوحة الإدارة على `/admin`. لتحديث الواجهة: أعد `npm run build`؛ ويمكن استخدام `npm run dev` لمراقبة ملفات React بعد أول بناء.

## قاعدة البيانات

طبّق ملفات SQL من 001 إلى 004 بالترتيب على مشروع Supabase جديد مخصص لياسمين ستور. إذا طبقت الكود الذي أرسل في المحادثة ونجح، لا تعِد تشغيله. جميع الأسعار مخزنة بالأغورة: 100 = شيكل واحد.

الجداول: `categories`, `products`, `orders`, `order_items`, `store_settings`. الجدول الأخير يبدأ بـ `accepting_orders=false`. حاوية `products` مخصصة لصور المنتجات العامة فقط، ولا تُستخدم لحفظ ملفات الزبائن.

تمنع RLS وصلاحيات الجداول وصول المتصفح المباشر. يحتفظ خادم ASP.NET بمفتاح `service_role`، وهو مفتاح سري يتجاوز RLS؛ يجب عدم وضعه في Git أو الواجهة أو المحادثة. دالتا إنشاء الطلب وتحديث حالته متاحتان لدور الخادم فقط.

## النشر على Render المجاني

1. اربط مستودع GitHub الخاص بخدمة Render.
2. أنشئ **Web Service** من هذا المستودع، واختر **Docker** و**Free**.
3. اترك مجلد الجذر فارغًا. ملف Docker في جذر المستودع.
4. أضف متغيرات البيئة التالية عبر إعدادات الخدمة فقط:

| المتغير | القيمة |
|---|---|
| `Supabase__Url` | رابط مشروع Supabase |
| `Supabase__ServiceKey` | مفتاح service_role السري من Supabase |
| `Admin__UserId` | UUID لمستخدم الإدارة في Supabase Auth |
| `Admin__RequireMfa` | `true` |
| `ASPNETCORE_HTTP_PORTS` | `8080` |
| `ASPNETCORE_ENVIRONMENT` | `Production` |

5. اضبط Health Check على `/api/health` وانشر الخدمة.

يمكن أيضًا استخدام `render.yaml` كـ Blueprint. لا يلزم شراء دومين للتجربة. الاستضافة المجانية قد تتوقف عند الخمول، ويستغرق أول فتح بعدها وقتًا. لا تعتمد على نظام ملفات Render لحفظ البيانات؛ البيانات والصور محفوظة في Supabase.

## حساب الإدارة

أنشئ مستخدمًا مؤكد البريد في **Supabase Authentication** ثم ضع UUID الخاص به في `Admin__UserId`. الحساب الإداري على منصة Supabase ليس تلقائيًا مستخدمًا لتطبيق المتجر.

نسخة الإنتاج تتطلب TOTP افتراضيًا. استخدم سكربت إعداد المصادقة `scripts/enroll-admin-mfa.mjs` لتسجيل عامل المصادقة قبل الدخول. لا تحفظ كلمة المرور أو رمز TOTP في Git.

تسجيل الدخول يستخدم Supabase للتحقق من البيانات ثم ملف جلسة ASP.NET مشفرًا وHttpOnly وSameSite=Strict. الجلسات صالحة لمدة 30 دقيقة وتُلغى عند إعادة تشغيل الخادم. عامل التحقق المعلق لا يتيح الوصول لبيانات الإدارة. مفاتيح الجلسات مؤقتة؛ يُشغّل التطبيق على نسخة خادم واحدة.

## قبل فتح الطلبات

- أضف صور المنتجات الحقيقية وأسعارها وكمياتها، وأزل علامة النموذج عن المنتجات القابلة للبيع.
- حدد رسوم ومناطق ومدة التوصيل ورقم التواصل.
- اعتمد سياسة الاستبدال والإرجاع؛ النص الحالي يشير إلى أنها لم تُعتمد بعد.
- اختبر طلبًا ثم التجهيز والشحن والتسليم والإلغاء واستعادة المخزون والتكرار والتزامن.
- تحقق من رفض دخول غير الأدمن ومن تفعيل العامل الثاني.
- اختبر الهاتف والكمبيوتر ورفع الصور ونسخ البيانات الاحتياطية.
- بعد التحقق، افتح استقبال الطلبات من إعدادات الإدارة.

## الحماية وحدود التحقق

CSRF على التغييرات، وتحديد معدل المحاولات، وCSP، وحماية التضمين، وعدم كشف أخطاء قاعدة البيانات. السعر والمخزون يحسبان على الخادم داخل معاملة PostgreSQL، مع قفل المخزون ومنع تكرار الطلب بنفس المفتاح. إلغاء الطلب يعيد الكمية مرة واحدة ضمن انتقالات حالة محددة.

تم بناء الواجهة والباك إند، وفحص API محليًا للتحقق من منع الوصول غير المصرح وحماية CSRF وتعطيل الطلبات قبل الإعداد. لم يكتمل اختبار متصفح أو اختبار Supabase مباشر بعد. هذه الضوابط لا تعني ضمان الحماية من جميع الهجمات. حدود معدل الطلبات مرتبطة بالذاكرة وبعنوان الاتصال؛ خلف وكيل Render قد يشترك الزوار في الحد نفسه، ويجب ضبط الوكيل الموثوق وتحديد المعدل قبل الإطلاق التجاري.
